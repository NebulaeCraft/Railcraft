# 客制轨道套件护目镜可见性调整记录

记录日期：2026-07-26

## 目标

以下四种轨道使用客制 3D 模型：

- 电力轨道（`electric`）
- 电力高速轨道（`high_speed_electric`）
- 高速轨道（`high_speed`）
- 强化轨道（`reinforced`）

它们安装轨道套件后必须继续使用原有客制轨道基底。除客制缓停套件外，其他可安装套件默认不改变轨道外观；铁路工护目镜新增 `Track`（轨道）模式，用于查看这些默认隐藏的套件。

## 原因定位

组合式轨道的模型由 `OutfittedTrackModel` 拼合：

```text
最终模型 = 轨道类型基底模型 + 轨道套件模型
```

四种目标轨道的客制基底钢轨顶面最高到模型坐标 `Y=2`，而通用套件的主要几何通常最高只到约 `Y=1.05`。直接拼合时，套件与客制钢轨及枕木发生穿插并被遮挡，因此只显示部分套件。

## 实现

### 默认外观

`OutfittedTrackModel` 只对四种目标轨道的 `COMPOSITE` 套件应用隐藏规则：

- 缓停套件 `TrackKits.BUFFER_STOP` 始终按原有方式显示。
- 其他组合式套件默认不加入方块的 baked quad 列表。
- 轨道类型基底始终取原有 `tracks/outfitted/type/...` 模型，不切换为官方模型，也不替换贴图。
- `UNIFIED` 类型的内部道岔模型逻辑保持不变。

因此安装默认隐藏的套件后，外观与未安装套件的客制轨道一致，套件行为、状态、碰撞与掉落均未改变。

### 护目镜 Track 模式

`ItemGoggles.GoggleAura` 末尾新增 `TRACK`，避免改变现有模式的 NBT 序号。显示名称复用项目已有的 `gui.railcraft.bore.track` 翻译键，因此无需修改顶层 `lang` 子模块，并可沿用现有多语言翻译。

客户端 `TrackKitVisibilityManager` 每个客户端 tick 检查本地玩家是否佩戴处于 `TRACK` 模式的铁路工护目镜。状态变化时调用 `RenderGlobal.loadRenderers()`，使已加载区块立即按新可见性重新烘焙。

`OutfittedTrackModel` 只读取管理器维护的 `volatile` 布尔值，不在区块构建线程中读取玩家物品栏。

### 完整显示

进入 `TRACK` 模式后，目标套件恢复渲染。最初曾将套件层整体向上移动一个模型单位：

```text
1 / 16 方块
```

补齐完整轨枕后，这个临时避让高度会让套件明显悬浮。现在改为按新基底的接触面精确对齐：通用套件最低点为模型坐标 `Y=-0.05`，完整轨枕顶面为 `Y=0.3`，因此套件只上移 `0.35` 个模型单位：

```text
0.35 / 16 方块（0.021875 方块）
```

移动在 baked quad 顶点数据的 Y 坐标上完成。这样套件底面贴合完整轨枕顶面，不再为了越过高度为 `Y=2` 的钢轨而悬浮。平直和坡道套件使用同一世界 Y 方向偏移规则。

为避免区块重建时重复分配顶点，偏移后的套件 quad 在模型烘焙时生成一次并缓存，之后由区块构建线程只读使用。

### 套件基底的完整轨枕

游戏内复测发现，通用套件模型只包含套件组件，并不自带完整枕木；它依赖轨道类型基底提供枕木。四种客制轨道的底层枕木原本各自只有左右两段（模型坐标 `X=0.5..4.5` 与 `X=11.5..15.5`），因此 Track 护目镜显示套件时，中央 `X=4.5..11.5` 会明显透空。

`MergedSleeperModel` 只在四种目标轨道的默认隐藏套件被 Track 护目镜显示时应用于轨道基底：

- 几何尺寸与贴图以现有客制道岔 `track_turnout_0.json` 的完整轨枕 cube 为基准：横向范围 `0.5..15.5`、厚度 `0..0.3`、每根纵向宽度 2，并沿用 `nebulaecraft:blocks/rail_bed`。
- 识别客制基底使用的 `nebulaecraft:blocks/rail_bed` 底层枕木材质。
- 将左右枕木的内侧边缘分别从 `X=4.5`、`X=11.5` 延伸到中心 `X=8`，两半在中心无缝接合，形成横贯两条钢轨下方的完整大轨枕。
- 同时处理模型烘焙后的 X/Z 方向，因此平直南北、平直东西及四种坡道方向均适用。
- 只变换底层枕木 quad，不改变钢轨、上层扣件、贴图或套件组件。
- 未戴 Track 护目镜时仍使用完全相同的原客制基底；客制缓停套件也继续走原渲染路径，不受此变换影响。

变换后的基底 quad 同样在模型烘焙时生成并缓存，区块重建阶段不会重复修改顶点数据。

## 附件使用情况

分析时确认附件包含官方电力套件基底，但最终方案必须保持四种轨道的客制基底不变，所以没有从附件复制或替换任何模型。修复完全在本地组合模型逻辑中完成。

## 建议的游戏内复测

1. 对四种目标轨道分别安装除缓停外、且该轨道类型允许安装的套件，确认未戴护目镜时外观与基础客制轨道一致。
2. 对允许安装缓停套件的目标轨道安装缓停套件，确认任何模式下仍显示客制缓停外观。
3. 戴上处于 `Track` 模式的铁路工护目镜，确认已加载区块中的隐藏套件立即出现，轨道基底不变化。
4. 从头顶、侧面及斜角检查平直套件，确认套件不再被客制钢轨遮挡。
5. 对允许坡道放置的套件检查四种坡道方向。
6. 脱下护目镜或切换到其他模式，确认套件重新隐藏且无需重新进入世界。
7. 检查普通铁轨、镀铁轨道和废弃轨道，确认其套件显示逻辑不受影响。
